This project is a real-world case study of the Log4Shell vulnerability (CVE-2021-44228) with a controlled local demonstration using a self-built Java web application, Log4j, Maven, OWASP ZAP, PowerShell, curl, and Python. The application runs on 127.0.0.1:8081, while ZAP is used as a proxy on 127.0.0.1:8080 to capture HTTP requests. The vulnerable stage uses Log4j 2.14.1, where controlled tests are performed using ${java:version}, a JNDI-style input, and a User-Agent lookup expression. ZAP preserves the original requests, while logs/app.log shows how the application recorded the inputs. The saved evidence is analysed using detect.py, which searches for suspicious Log4j-style patterns and generates SHA-256 hashes for evidence integrity. After evidence collection, Log4j is upgraded from 2.14.1 to 2.17.1 and the same tests are repeated for comparison. After the patch, ${java:version} remains as literal text instead of being evaluated as Java version 17.0.17. The JNDI-style test was captured, but no successful lookup or code execution was established. The project therefore demonstrates forensic evidence collection, analysis, and remediation verification without reproducing remote code execution.
